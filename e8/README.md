# Experimental HAWK-E8-CM

Research code for HAWK instantiated with the E8 lattice. Everything specific
to E8 lives in this directory; the rest of the repository is upstream HAWK and
is kept byte-identical to the upstream merge commit (`make check-upstream`
from the repository root).

Design notes: [`docs/HAWK_E8_VARIANT.md`](docs/HAWK_E8_VARIANT.md).

## Layout

```text
e8/
  Makefile    builds against ../Reference_Implementation (generated by ../build.py)
  src/        E8 scheme sources: hawk_e8.h (public API), e8_*.c,
              hawk_e8_inner.h (internal declarations)
  common/     shared measurement modules, used identically for HAWK and E8:
                cmn_rng     SHAKE256 streams (128-byte buffer, byte
                            counters) and the benchmark signing RNG
                cmn_pool    spin/yield worker pool with per-worker CPU and
                            core-cycle accounting
                cmn_timing  fenced TSC, CLOCK_MONOTONIC_RAW,
                            CLOCK_THREAD_CPUTIME_ID, perf core cycles
                cmn_csv     CSV writer and the per-signature schema
  tests/      E8 correctness tests (test_e8_*.c) and test_cmn_common.c
  tools/      diagnostics: histograms, rejection summary, validation summary
  compare/    HAWK vs E8 benchmarks
    e8_sign_bench.c          HAWK vs E8 signing, all_in and prepared accounting
    hawk_shim.c/.h           the only bridge to static HAWK internals
    hawk_sign_profile.patch  stage profiling applied to a copy of hawk_sign.c
  docs/       design notes and recorded performance results
```

Dependencies run one way: `src/` may use `common/`; `compare/` (and
`tests/`, `tools/`) may use both; `common/` uses neither, only upstream
HAWK's `sha3.h` and `hawk.h`. The scheme therefore never depends on the
benchmarks. Common objects are built in `build/common/`.

## Usage

From the repository root (targets forward here), or with `make -C e8 <target>`:

```sh
make e8                  # build all E8 tests, tools and benchmarks
make test-e8             # run the E8 test suite
make check-upstream      # confirm upstream HAWK files are unchanged
```

Benchmarks and diagnostics: `sampler-bench`, `profile-sampler-bench`,
`sign-bench`, `profile-sign-bench`, `profile-hawk-sign-bench`,
`e8-histograms`, `e8-rejection-summary`, `e8-validation-summary`,
`e8-sigma-verify-sweep`, `e8-sigma-sign-sweep`. CSV outputs are written to
`e8/`.

For timing, disable the prototype debug checks, for every object alike:

```sh
make -C e8 clean
make -C e8 sign-bench CFLAGS='-O2 -DHAWK_E8_DEBUG_CHECKS=0'
```

In-path instrumentation is off by default (`HAWK_E8_PROFILE_SAMPLER=0`,
`HAWK_E8_PROFILE_SIGN=0`). Only the `profile-*` targets and the rejection
summary are built with it, and their timings include the profile timers.

## Rules

- Do not edit upstream HAWK files (`src/`, `extra/`, `intermediate/`,
  `build.py`, `Reference_Implementation/`, `Optimized_Implementation/`).
- Benchmarks that need static HAWK internals add a wrapper to
  `compare/hawk_shim.c` instead of including `hawk_sign.c` themselves.
- HAWK objects are compiled with the upstream reference flags; E8 objects
  with `-DHAWK_ENABLE_E8_EXPERIMENTAL=1`.

The E8 code is experimental: floating-point, data-dependent and not
constant-time. It is not suitable for deployment.
