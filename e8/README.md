# Experimental HAWK-E8-CM

Research code for HAWK instantiated with the E8 lattice. Everything specific
to E8 lives in this directory; the rest of the repository is upstream HAWK and
is kept byte-identical to the upstream merge commit (`make check-upstream`
from the repository root).

Design notes: [`docs/HAWK_E8_VARIANT.md`](docs/HAWK_E8_VARIANT.md).

## Layout

```text
e8/
  Makefile    builds against ../Reference_Implementation (generated by ../build.py)
  src/        E8 scheme sources: hawk_e8.h (public API), e8_*.c,
              hawk_e8_inner.h (internal declarations); the sampler
              variants (e8_sampler_ref.c, e8_sampler_hot.c built once per
              width, registry e8_sampler_variants.c) and the test/tool-only
              runtime table builder (e8_sampler_runtime.c)
  tables/     gen_tables.py, the offline generator (Python standard
              library), and the generated integer sampler tables of every
              variant of both schemes:
                e8_tables_geom.h              E8 geometry (all variants)
                e8_tables_{ref,hot64,hot32}.h E8 variant tables, per logn
                hawk_tables_{ref,hot64,hot32}.h  HAWK variant tables
  common/     shared measurement modules, used identically for HAWK and E8:
                cmn_rng     SHAKE256 streams (128-byte buffer, byte
                            counters, prefixed streams) and the benchmark
                            signing RNG
                cmn_pool    spin/yield worker pool (dispatch only grows it)
                            with per-worker CPU and core-cycle accounting
                cmn_timing  fenced TSC, CLOCK_MONOTONIC_RAW,
                            CLOCK_THREAD_CPUTIME_ID, perf core cycles
                cmn_csv     CSV writer and the per-signature schema
  tests/      E8 correctness tests (test_e8_*.c), test_hawk_variants.c and
              test_cmn_common.c
  tools/      diagnostics: histograms, rejection summary, validation summary;
              precision_audit.py (SD and Renyi divergence of every sampler
              variant from the committed tables)
  compare/    HAWK vs E8 benchmarks
    e8_sign_bench.c          HAWK vs E8 signing, every sampler variant,
                             all_in and prepared accounting
    e8_sampler_bench.c       sampler timing (--variant-matrix: every variant)
    hawk_shim.c/.h           the only bridge to static HAWK internals
    hawk_sign_profile.patch  stage profiling applied to a copy of hawk_sign.c
    hawk_variants/           benchmark-only HAWK sampler variants:
      hawk_sign_variant.patch   upstream hawk_sign.c with the sampler call
                                routed through a hook, renamed entry points
                                (applied to a copy in build/)
      hawk_variants.c/.h        registry, selection, bound worker streams
      hawk_sampler_hot.c        hot64/hot32 (built once per width)
      hawk_sampler_ref.c        ref-T (upstream table and scan)
  docs/       design notes, recorded performance results, the precision
              audit (precision_audit.md, precision_summary.csv)
```

Dependencies run one way: `src/` may use `common/` and `tables/`;
`compare/` (and `tests/`, `tools/`) may use all three; `common/` uses
neither, only upstream HAWK's `sha3.h` and `hawk.h`. The scheme therefore never depends on the
benchmarks. Common objects are built in `build/common/`.

## Usage

From the repository root (targets forward here), or with `make -C e8 <target>`:

```sh
make e8                  # build all E8 tests, tools and benchmarks
make test-e8             # run the E8 test suite
make check-upstream      # confirm upstream HAWK files are unchanged
make tables              # regenerate the sampler tables; fail if they differ
make check-integer-only  # the signing paths contain no floating point
make precision-audit     # SD / Renyi audit of every variant (docs/precision_audit.md);
                         # fail if docs/precision_summary.csv differs
```

Benchmarks and diagnostics: `sampler-bench`, `variant-sampler-bench`,
`profile-sampler-bench`,
`sign-bench`, `profile-sign-bench`, `profile-hawk-sign-bench`,
`e8-histograms`, `e8-rejection-summary`, `e8-validation-summary`,
`e8-sigma-verify-sweep`, `e8-sigma-sign-sweep`. CSV outputs are written to
`e8/`.

For timing, disable the prototype debug checks, for every object alike:

```sh
make -C e8 clean
make -C e8 sign-bench CFLAGS='-O2 -DHAWK_E8_DEBUG_CHECKS=0'
```

In-path instrumentation is off by default (`HAWK_E8_PROFILE_SAMPLER=0`,
`HAWK_E8_PROFILE_SIGN=0`). Only the `profile-*` targets and the rejection
summary are built with it, and their timings include the profile timers.

## Rules

- Do not edit upstream HAWK files (`src/`, `extra/`, `intermediate/`,
  `build.py`, `Reference_Implementation/`, `Optimized_Implementation/`).
- Benchmarks that need static HAWK internals add a wrapper to
  `compare/hawk_shim.c` instead of including `hawk_sign.c` themselves.
- HAWK objects are compiled with the upstream reference flags; E8 objects
  with `-DHAWK_ENABLE_E8_EXPERIMENTAL=1`.
- Benchmark-only HAWK variants live in `compare/hawk_variants/`; files
  derived from upstream `hawk_sign.c` are headed "derived from upstream
  hawk_sign.c, modified for benchmarking", and the upstream source is only
  ever patched into a copy under `build/`.
- Sampler tables come only from `tables/gen_tables.py`; edit the generator,
  regenerate, and let `make tables` confirm.

The E8 code is experimental. Its signing path is integer-only, but the
`hot64` and `hot32` samplers are data-dependent and not constant-time, and
the `ref` sampler's constant-time structure is tested only structurally. It
is not suitable for deployment.
